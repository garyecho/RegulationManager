## 1. Product Overview

### 1.1 产品名称
**央行评级标准打分卡模块**（挂载于「制度汇编管理系统」内，作为其业务子模块）

### 1.2 愿景
把《央行评级专业评价指标体系》两份标准打分卡内建到桌面系统中，让使用者可以按层级浏览、检索、维护打分卡条目，并能从"评分要点"直接打开程序里已导入的对应制度文件。

### 1.3 背景
公司内部制度汇编管理系统已能管理制度文档（分类、标签、全文检索）。评级专业人员在实际工作中需要对照"央行评级专业评价指标体系"逐项核查制度，当前只能翻阅 Excel 原文、再另开制度库搜索对应文件，效率低且容易漏项。本模块把打分卡与制度库打通。

### 1.4 核心价值
| 价值 | 说明 |
|------|------|
| 结构即查 | 打分卡四层结构在桌面端可直接钻取浏览，替代翻 Excel |
| 制度即点 | 评分要点/检查项可关联已导入制度文档，一键打开正文 |
| 可维护 | 模块名、评分要点等内容可直接修改，随监管要求演进 |
| 秒级定位 | 关键词搜索直接跳到打分卡对应选项 |

### 1.5 目标用户
- **主要用户**: 评级专业人员 / 制度管理人员（单机使用）
- **使用模式**: 日常对照打分卡逐条核查制度；内容更新时编辑打分卡条目

### 1.6 约束
| ID | 约束 |
|----|------|
| C1 | 沿用现有技术栈：PyQt5 + SQLAlchemy + SQLite（单机桌面应用），Python 3.8 语法约束（`typing.Dict/List`，禁止 3.9+ 语法） |
| C2 | 中文界面（与现有应用一致） |
| C3 | 所有数据持久化在现有 `data/regulation.db`（新表），遵循现有"启动即迁移/建表"机制（`database/migrations.py`） |
| C4 | 关联目标 = 现有 `documents` 表中的制度文档（含标题、文号、分类、正文 `content_text`） |
| C5 | 内置的两份标准打分卡为**离线初始数据**，首次启动自动入库，不依赖网络 |
| C6 | 不引入新依赖：搜索用 SQL LIKE 即可（打分卡总条目约 400 行级，无需 FTS） |

## 2. User Stories

### 2.1 Epic 1：打分卡浏览与钻取导航（E1，对应需求一、二）

#### US-E1-001: 选择适用银行类型进入打分卡
**As a** 评级专业人员
**I want to** 在打分卡入口选择适用银行类型（城商/农商/民营 或 村镇银行）
**So that** 我看到的是与评级对象匹配的那套标准

**Acceptance Criteria (EARS):**
| ID | 类型 | 验收标准 |
|----|------|----------|
| AC-E1-01 | Ubiquitous | 系统 SHALL 内置两份标准打分卡（「城商、农商、民营」「村镇银行」），其内容与 xls 两 Sheet 一致 |
| AC-E1-02 | Event-Driven | WHEN 用户切换银行类型，THEN 系统 SHALL 切换到对应打分卡并清空/刷新已选层级状态 |
| AC-E1-03 | Unwanted | IF 切换类型后，THEN 系统 SHALL NOT 展示另一份打分卡的条目 |

#### US-E1-002: 按层级钻取打分卡内容
**As a** 评级专业人员
**I want to** 从"模块 → 一级指标 → 二级指标"逐级点选，查看每个评分检查项（评级内容）及其全部说明字段
**So that** 能像翻打分卡一样逐条核查

**Acceptance Criteria (EARS):**
| ID | 类型 | 验收标准 |
|----|------|----------|
| AC-E1-04 | Ubiquitous | 系统 SHALL 以 模块→一级指标→二级指标→评级内容 四层结构组织打分卡，且支持逐级下钻与返回 |
| AC-E1-05 | Ubiquitous | 系统 SHALL 展示每个评级内容条目的全部字段：评分要点、监管制度和条款（依据）、需调阅材料（清单） |
| AC-E1-06 | Event-Driven | WHEN 用户点击某个二级指标/检查项，THEN 系统 SHALL 在内容区展示该节点下的全部条目 |
| AC-E1-07 | Unwanted | 系统 SHALL NOT 展示层级归属错误的条目（空/占位行不得产生孤立节点） |

> 层级数据说明：xls 一行 = 一条"评级内容"检查项；其 模块/一级/二级 取该行上方最近的非占位（非 '0'）单元格；列 4「评分」为空且现场打分不属于本模块范围，不建模、不展示。

### 2.2 Epic 2：评分要点 ↔ 制度文档关联与打开（E2，对应需求三）

#### US-E2-001: 关联制度文档
**As a** 评级专业人员
**I want to** 给某个评级内容条目（或其评分要点）手动指定关联的已导入制度文档
**So that** 之后一键即可打开对应的制度原文

**Acceptance Criteria (EARS):**
| ID | 类型 | 验收标准 |
|----|------|----------|
| AC-E2-01 | Event-Driven | WHEN 用户在条目编辑界面点击"选择关联制度"，THEN 系统 SHALL 展示现有制度文档选择器（支持按标题/文号筛选） |
| AC-E2-02 | Ubiquitous | 系统 SHALL 允许一个条目关联 0..N 份制度文档 |
| AC-E2-03 | Optional | IF 条目编辑界面提供"按文件名/标题自动建议"辅助，THEN 系统 SHALL 仅给出候选（供勾选），不自动落库 |
| AC-E2-04 | Unwanted | 系统 SHALL NOT 允许关联到已软删除（回收站）或不存在的文档 |

#### US-E2-002: 从条目打开制度正文
**As a** 评级专业人员
**I want to** 点击条目上的关联文档链接，直接打开该文件正文
**So that** 对照监管要点核对该制度内容不用再去文档列表里翻找

**Acceptance Criteria (EARS):**
| ID | 类型 | 验收标准 |
|----|------|----------|
| AC-E2-05 | Event-Driven | WHEN 用户点击条目的关联文档链接，THEN 系统 SHALL 打开该文档（沿用现有"打开文件"行为；文件缺失时提示并允许解除关联） |
| AC-E2-06 | Ubiquitous | 系统 SHALL 在条目详情中明确显示已关联文档的标题，无关联时显示"未关联"占位 |
| AC-E2-07 | Unwanted | IF 关联文档的物理文件已不存在，THEN 系统 SHALL NOT 崩溃，SHALL 提示文件缺失 |

### 2.3 Epic 3：打分卡内容维护（E3，对应需求四）

#### US-E3-001: 修改模块名称与内容字段
**As a** 制度/评级内容维护人员
**I want to** 直接修改模块名称、一级/二级指标名称、评级内容文本、评分要点、监管依据、调阅材料等字段
**So that** 监管口径变化后打分卡能随之更新，无需改动程序

**Acceptance Criteria (EARS):**
| ID | 类型 | 验收标准 |
|----|------|----------|
| AC-E3-01 | Event-Driven | WHEN 用户在条目/节点的编辑界面保存修改，THEN 系统 SHALL 将改动持久化到数据库并即时刷新界面 |
| AC-E3-02 | Ubiquitous | 系统 SHALL 允许对 模块、一级指标、二级指标、评级内容条目 进行改名与文本字段编辑 |
| AC-E3-03 | Ubiquitous | 系统 SHALL 在每次保存前做非空校验（名称/内容不得为空） |
| AC-E3-04 | Unwanted | IF 名称或内容为空，THEN 系统 SHALL NOT 允许保存 |
| AC-E3-05 | Unwanted | 系统 SHALL NOT 允许把某层级节点的名称改成与同父级下另一节点重名（同层唯一） |

> 范围说明：需求四按"修改内容"理解；**新增/删除**层级节点不在本期验收范围（编辑界面只做改名+改文本+改关联）。是否需要增删节点请在评审时确认。

### 2.4 Epic 4：打分卡关键词搜索与跳转（E4，对应需求五）

#### US-E4-001: 搜索并跳转到命中选项
**As a** 评级专业人员
**I want to** 输入关键词搜索打分卡内容，命中后点击结果直接跳到打分卡中对应选项位置
**So that** 不用逐层翻找就能定位某条监管要求/材料清单

**Acceptance Criteria (EARS):**
| ID | 类型 | 验收标准 |
|----|------|----------|
| AC-E4-01 | Event-Driven | WHEN 用户输入关键词并触发搜索，THEN 系统 SHALL 在当前银行类型打分卡的 模块/一级/二级/评级内容/评分要点/依据/材料 字段中做包含匹配并列出命中条目（含所属层级路径） |
| AC-E4-02 | Event-Driven | WHEN 用户点击某条搜索结果，THEN 系统 SHALL 展开并高亮定位到打分卡树中对应选项 |
| AC-E4-03 | Ubiquitous | 系统 SHALL 在搜索结果中显示空关键词提示（空输入不搜索） |
| AC-E4-04 | Optional | IF 搜索结果跨多层级命中，THEN 系统 SHALL 按"层级路径"分组或排序展示，保证可读 |
| AC-E4-05 | Unwanted | 系统 SHALL NOT 在无结果时抛出异常；SHALL 显示"无匹配结果" |

## 3. Non-Functional Requirements

### 3.1 性能
| ID | 指标 | 目标 |
|----|------|------|
| NFR-PERF-001 | 打分卡数据量 | 单份 ≤ 约 300 条目、≤ 9 模块，整库两份 |
| NFR-PERF-002 | 搜索响应 | LIKE 搜索 ≤ 300ms（本地 SQLite 即时返回） |
| NFR-PERF-003 | 启动影响 | 首次启动自动建表+灌入内置数据 ≤ 3s；后续启动不重复灌入 |

### 3.2 安全
| ID | 需求 | 实现 |
|----|------|------|
| NFR-SEC-001 | 单机本地数据 | 数据存本地 SQLite，无网络传输（与现有应用一致） |
| NFR-SEC-002 | 非法输入防护 | 编辑输入经 SQLAlchemy 参数化 + 长度/非空校验，防注入与脏数据 |

### 3.3 可靠性
| ID | 需求 | 目标 |
|----|------|------|
| NFR-REL-001 | 编辑持久化 | 保存即写库（沿用现有 session 事务模式），崩溃不丢已保存内容 |
| NFR-REL-002 | 初始数据幂等 | 内置打分卡灌入逻辑重复执行不产生重复数据（按唯一键判断） |

### 3.4 可用性
| ID | 需求 | 实现 |
|----|------|------|
| NFR-USA-001 | 中文界面 | 全部菜单/按钮/提示为中文 |
| NFR-USA-002 | 层级可达性 | 从打分卡入口到任一检查项 ≤ 4 次点击 |
| NFR-USA-003 | 反馈 | 保存/关联/删除关联等操作以现有 Toast 组件给出结果反馈 |

### 3.5 成本
| ID | 需求 | 目标 |
|----|------|------|
| NFR-COST-001 | 依赖约束 | 不新增第三方 Python 依赖（xls 导入下期另评估解析库） |

## 5. Glossary

| 术语 | 定义 |
|------|------|
| 打分卡（评分卡） | 央行评级专业评价指标体系，按银行类型分为「城商、农商、民营」与「村镇银行」两套 |
| 模块 | xls 列 0，打分卡最顶层，如"一、公司治理"，共 9/8 个 |
| 一级指标 | xls 列 1，如"（一）组织架构"，城商版 31 个 / 村镇版 28 个 |
| 二级指标 | xls 列 2，评价主题，如"1.加强党的领导"，城商版 84 个 / 村镇版 63 个 |
| 评级内容 | xls 列 3，二级指标下的具体检查项/扣分条件文本 |
| 评分要点 | xls 列 5，打分/扣分细则说明 |
| 监管制度和条款（依据） | xls 列 6，引用监管法规原文 |
| 需调阅材料（清单） | xls 列 7，检查时应索要的材料 |
| 占位行 | xls 中二级指标单元格为 '0' 的行，表示继承上方最近一个二级指标，不入库为独立节点 |
| Profile / 银行类型 | 打分卡适用对象标识（城商农商民营 / 村镇银行） |
